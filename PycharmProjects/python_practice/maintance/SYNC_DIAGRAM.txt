SCENARIO 1: USER CHANGES PAYMENT TO PAID

SYNC LOGIC DECISION TREE:
═════════════════════════════════════════════════════════════════════════════

User changes Payment?
  ├─ YES → Sync maintenance_paid_months with current_month
  │        (Add if 'paid', Remove if 'not_paid')
  │        Trigger: set_payment()
  │
  └─ NO  → User changes Maintenance?
           ├─ YES → Is month == current_month?
           │        ├─ YES → Sync payment_status
           │        │        Trigger: set_maintenance()
           │        └─ NO  → Don't sync
           │                 (Allow independent maintenance)
           │
           └─ NO  → No sync needed

DATABASE STATE EXAMPLES:
═════════════════════════════════════════════════════════════════════════════

Example 1: Fully Synced for Current Month
──────────────────────────────────────────
H-001:
  payment_status: 'paid'
  maintenance_paid_months: '2026-02'
  (Current month 2026-02 is in maintenance list)
  (Both show: ✅ PAID)

Example 2: Multiple Maintenance Months
───────────────────────────────────────
H-002:
  payment_status: 'paid'
  maintenance_paid_months: '2026-01,2026-02,2026-03'
  (Current month 2026-02 is in list → Synced)
  (Also has past month 2026-01 and future month 2026-03)

Example 3: Not Paid with Future Maintenance
─────────────────────────────────────────────
H-003:
  payment_status: 'not_paid'
  maintenance_paid_months: '2026-03,2026-04'
  (Current month 2026-02 is NOT in list → Payment is NOT PAID)
  (But has maintenance for future months - independent)

Example 4: Just Added Maintenance
──────────────────────────────────
H-004:
  payment_status: 'not_paid'
  maintenance_paid_months: ''
  (No months paid)
  (Both show: ❌ NOT PAID)

SYNC RULES SUMMARY:
═════════════════════════════════════════════════════════════════════════════

Rule 1: Current Month Only
──────────────────────────
  Only the current month (2026-02) is synced with payment_status.
  Past and future months are independent.

Rule 2: Bidirectional
─────────────────────
  Payment → Maintenance: When payment changes, maintenance changes
  Maintenance → Payment: When current month maintenance changes, payment changes

Rule 3: Consistent State
────────────────────────
  If payment_status = 'paid' → 2026-02 MUST be in maintenance_paid_months
  If payment_status = 'not_paid' → 2026-02 MUST NOT be in maintenance_paid_months

Rule 4: Independent Future
──────────────────────────
  You can add maintenance for any past/future month without affecting payment
  Example: House can be "Not Paid" but have maintenance for 2026-03

Rule 5: All-or-Nothing
──────────────────────
  Sync either fully completes or doesn't happen (database transaction)
  No partial updates
